# Native Android history checks

## Coverage

- `HistoryFixtureTest` runs the shared `transaction-history.json`,
  `history-regressions.json` and `bark-movement.json` cases as individual
  parameterized JUnit tests. It adapts RN fixture records to SDK records and compares
  every JSON field, including omitted values. Fixtures are read as test resources and
  are not modified.
- `HistoryModelTest` covers unavailable/suspended wallets, historical timestamp and
  currency, daily cache keys, current-rate fallback, offline quotes, publication
  before enrichment, overlapping refreshes, cancellation, observer subscription and
  resubscription, block-time enrichment before merge, signed filtered CSV escaping,
  and explorer variants.
- `WalletSessionTest` verifies that canceling a history caller still finishes both
  native reads before closing the handles.

## Running

From the repository root (Nix supplies JDK 17):

```sh
nix develop --command sh -c 'cd apps/android && ./gradlew :app:testRegtestDebugUnitTest :app:assembleRegtestDebug'
```

Regenerate the RN-derived fixtures (`transaction-history.json`, `bark-movement.json`)
with `bun --tsconfig-override client/tsconfig.json apps/fixtures/tools/generate-history.ts`;
`history-regressions.json` is not generated by it.

## Manual regtest check

Use a disposable emulator against the regtest stack (the app reaches it at
`10.0.2.2`). Receive over Ark, Lightning and on-chain, mine with `just generate 1`
and refresh: unconfirmed on-chain rows sort first and confirmed rows show the block
label (regtest has no Esplora date lookup). Exercise the filters, the detail
sheet/two-pane layout and CSV export. Exports live in `cacheDir/history-exports/`
and expire after 24 hours. Don't commit screenshots or payment identifiers.
